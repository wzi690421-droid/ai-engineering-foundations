# Week 01 Day 01 学习复盘

## 1. `topKDistinct` 的完整处理流程

`topKDistinct` 通过只读引用接收一个 `vector<int>`，同时接收需要保留的元素数量 `k`。只读引用可以避免复制原数组，并保证函数不会修改调用者传入的数据。

函数先把输入复制到局部变量 `nums`，然后使用 `std::sort` 和 `std::greater<int>` 将 `nums` 从大到小排序。接着，`std::unique` 把相邻的重复元素移动到有效区间之后，并返回有效区间末尾的迭代器；`erase` 再真正删除这些重复元素。

如果去重后的元素数量大于 `k`，就使用 `resize(k)` 截断，只保留最大的 `k` 个不同元素；如果元素数量不超过 `k`，则直接保留全部元素。最后返回处理后的 `nums`。

## 2. 为什么要先排序再使用 `unique`

`std::unique` 只能识别并处理相邻的重复元素。排序可以把相同数字放到一起，因此 `unique` 才能完整地找出所有重复项。这里使用从大到小排序，还能让去重后的数组保持从大到小的顺序。

## 3. 两种重复检测方法的复杂度

- 双重循环：时间复杂度最坏为 `O(n²)`，额外空间复杂度为 `O(1)`。
- 哈希集合：平均时间复杂度为 `O(n)`，额外空间复杂度为 `O(n)`；极端哈希冲突时，时间复杂度可能退化。

双重循环虽然最坏情况慢，但如果重复元素很早就能被发现，它可能因为没有创建哈希表而更快。哈希集合更适合数据量较大，或者需要扫描很多元素才能发现重复的情况。

## 4. 为什么不能使用 `find(value) == 0`

`unordered_set::find(value)` 返回的是迭代器，不是元素值、数组下标或整数。找到元素时，它返回指向该元素的迭代器；没有找到时，它返回 `seen.end()`。

因此正确判断方式是：

```cpp
seen.find(value) != seen.end()
```

把迭代器和 `0` 比较不符合这个接口的语义。即使某个环境中碰巧编译、运行并通过了现有测试，也不能说明写法正确或可移植。

## 5. 为什么不适合使用 `size_t value` 遍历 `vector<int>`

`size_t` 是无符号整数类型，只能表示非负整数，而 `vector<int>` 中可能包含负数。如果把 `-1` 赋给 `size_t`，它会按照无符号整数的规则转换成一个很大的正数；在常见的 64 位环境中通常是 `18446744073709551615`。

这样会改变原数据的数值含义，并可能在比较或哈希查询时引入隐式类型转换。即使转换过程中又碰巧得到原来的结果，也不能依赖这种行为。遍历 `vector<int>` 时应使用 `int value`，或者让编译器推导类型：

```cpp
for (int value : nums)
```

```cpp
for (const auto& value : nums)
```

## 6. `reserve` 什么时候有帮助，什么时候可能有害

当预计要插入很多元素时，提前调用 `reserve` 可以减少哈希表扩容和重新散列的次数，从而缩短运行时间。

如果程序在前几个元素就发现重复并提前返回，那么提前预留很大的空间反而没有得到利用，还会增加空间开销和初始化成本，可能拖慢程序。
